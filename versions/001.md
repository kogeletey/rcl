# RCL v1 Specification

## 1. Scope

RCL is a block-oriented configuration language with Ruby-like `do ... end` structure.
This document defines syntax, projection semantics, formatter rules, and conversion invariants.

## 2. Lexical Rules

### 2.1 Whitespace and comments

- Space, tab, and newline are separators.
- Newline is not a statement terminator.
- `#` starts a line comment until end-of-line.
- `//` comments are invalid.

### 2.2 Identifiers

- Identifier MUST match `[A-Za-z_][A-Za-z0-9_]*`.

### 2.3 Strings

- String literals MUST use double quotes (`"..."`).
- Supported escapes are exactly: `\"`, `\\`, `\n`, `\t`.
- Single-quoted strings are invalid.
- Unterminated strings and invalid escapes MUST fail.

### 2.4 Numbers and booleans

- Integers and decimal numbers are supported (`-42`, `0`, `3.14`).
- Boolean literals are `true` and `false`.

## 3. Grammar

```ebnf
program         ::= block*
block           ::= identifier argument? "do" statement* "end"
argument        ::= string
statement       ::= property | block
property        ::= property_key "=" value
property_key    ::= identifier ("." identifier)*
value           ::= string | number | boolean | array
array           ::= "[" (value ("," value)*)? "]"
```

Constraints:

- Bare identifier values are invalid (for example, `x = value`).
- Trailing comma in arrays is invalid.

## 4. Projection Model

Projection output is a JSON-like value (`object | array | scalar`).
Root projection is always an object.

## 5. Projection Semantics

For each block, produce object `B` as follows:

1. For each property `k = v`:
- Convert `v` to scalar/array value.
- Insert by dotted path (`a.b.c`) into nested objects.

2. For each unnamed child block `child do ... end`:
- Set/merge `B[child_name] = child_projection`.

3. For each named child block `child "arg" do ... end`:
- Compute `base = named_base(child_name)`.
- Set/merge `B[base][arg] = child_projection`.

4. Root object:
- For each root block, assign root key by the same rules.
- Root named block uses `named_base(root_name)` and argument map.

`named_base(name)` is deterministic and language-independent:
- Default rule: append `s` (`region -> regions`, `service -> services`).
- Implementations MUST NOT hardcode behavior for one specific block name.

## 6. Key Conflict Rules

Within the same block scope:

- Duplicate path is invalid: `a = 1` then `a = 2`.
- Prefix conflict is invalid:
- `a = 1` then `a.b = 2`
- `a.b = 1` then `a = 2`

These checks apply before projection output is emitted.

## 7. Canonical Formatting

Canonical formatter MUST:

- emit only double-quoted strings with valid escaping,
- emit explicit `do ... end` blocks,
- emit arrays with comma separator and no trailing comma,
- preserve semantic structure under parse -> format -> parse.

## 8. Native Conversions

Implementations expose conversion from projected object to:

- YAML
- TOML
- HCL

Required invariants:

- The three outputs MUST represent the same projected structure.
- Named-block projection shape MUST be preserved (`base -> arg -> object`).
- Scalar types (`string`, `number`, `boolean`) and arrays MUST be preserved.
- Conversion rules MUST be generic and not tied to specific sample keys.

## 9. Error Requirements

Parser MUST fail with line/column for at least:

- unexpected token or character,
- missing `end`,
- missing `]`,
- invalid bare identifier value,
- trailing comma in array,
- duplicate key,
- key-path prefix conflict,
- unterminated string,
- invalid escape,
- single-quoted string usage.
